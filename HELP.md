# Агент-стажёр — краткая справка

## Что это
Агент **intern** на базе opencode: наблюдает за вашими действиями, запоминает процедуры
в долговременную память (`agent-memory/`), обобщает на похожие задачи (сервер1 → сервер2)
и выполняет их, спрашивая разрешения на опасные шаги.

## Как работает (жизненный цикл)

1. **Наблюдение** — вы выполняете действия, агент собирает команды из сессии (`capture.py`).
2. **Запись в память** — команды размечаются: переменные (хост, порт, путь) — правилами
   и LLM; процедура сохраняется в `agent-memory/procedures/` (git-версионируется),
   генерируется человекочитаемая инструкция `instructions/<id>.md`.
3. **Поиск** — новая задача → `retrieve.py` ищет похожую процедуру (TF-IDF + keywords):
   уверенность ≥0.70 — выполняем, 0.40–0.70 — спрашиваем, <0.40 — новая задача (учимся).
4. **Классификация** — `classify.py`: **P0** (read-only, из allowlist) — без подтверждений;
   **P1/P2** (scp, systemctl, службы) — подтверждение в чате.
5. **Исполнение** — `run_procedure.py` подставляет параметры, выполняет шаги с лимитами,
   проверяет критерии успеха, обновляет статистику (runs/ok).
6. **Верификация** — провал → модификация и новая процедура; старая помечается
   «не работает» (поиск таких режет уверенность ×0.5); `verify-procedure.py` — независимая
   сверка критериев без изменения state.

Процедуры с **agent-шагами** (браузер, MCP: `type: agent` в шаге) исполняет сам интерн
в чате с подтверждениями (Playwright MCP, отдельный Chrome-профиль), а результат
фиксирует командой `mark_result.py` — это нужно для статистики и поиска.

## Как начать запоминание

Скажите интерну триггер + краткое описание:
```
«Запоминай: я делаю деплой приложения на сервер.
Шаги: scp архива, распаковка, перезапуск службы, проверка health.
Переменные: хост, порт, путь — будут меняться.
Успех = curl /health вернул 200.»
```

Дальше:
1. Выполняйте действия по одному (без посторонних команд между шагами).
2. Интерн покажет таблицу параметров (suggested / unsure) — подтвердите или поправьте:
   «PORT — переменная», «LOG_LEVEL — константа».
3. Финал: «Сохрани как процедуру "Деплой приложения", хост server1, порт 8080».
4. Следующая похожая задача — без обучения: «запусти приложение на сервере2».

## Полезные фразы

Процедуры запускаются **по смыслу** — не нужно называть id:
- «нет ли встреч в ближайшее время» → P003 «Проверка календаря»
- «запусти приложение на сервере2» → процедура деплоя (если запомнена)
- «выполни процедуру P002» — тоже работает (по id)

Если подходят **несколько** процедур — интерн покажет список с номерами
(по убыванию вероятности). Назовите номер — или просто подтвердите:
по умолчанию берётся вариант 1 (самый вероятный).

Ещё:
- «Начинай запоминать» / «Прекрати запоминать» — границы наблюдения
- «Это постоянное значение» / «Это будет меняться» — уточнения по параметрам
- «Успехом считаем ...» — критерий успеха (проверяется при исполнении)
- «Не записывай эту команду» — исключение шума
- «Выведи справку» — этот документ (или команда /intern)

## Безопасность (3 слоя)

1. **Permissions** (`opencode.json`): read-only разрешено; `rm`, `iex`, `diskpart`,
   деструктивный git — запрещено.
2. **Плагин guard.ts**: блокирует опасные команды (в т.ч. обфусцированные),
   маскирует секреты в выводе (REDACTED).
3. **Правила скилла**: сомнение → вопрос пользователю; подтверждения обязательны.

Память — per-проект: у каждого проекта свои процедуры; всё в git (история, откаты,
обновление шаблона через `git pull`).

## Скрипты (кратко)

- `python scripts/index.py` — пересборка индекса после изменений процедур
- `python scripts/stats.py` — сводка: успехи, latency, метрики по процедурам
- `python scripts/retrieve.py --query "..." --host <хост>` — поиск процедуры
- `python scripts/classify.py --command "..."` — уровень опасности P0/P1/P2
- `python scripts/run_procedure.py --procedure P002 --host <хост> --bindings "A=x" --approve-all` — исполнение
- `python scripts/mark_result.py --procedure P003 --host local --ok|--fail` — фиксация результата agent-процедуры
- `python scripts/verify-procedure.py --procedure P002 --host <хост>` — независимая сверка критериев
